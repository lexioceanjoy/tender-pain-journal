# Tender — initial data model

## Why define data before screens

The data model is the long-lived part of a health journal. Screens and visual design will evolve, but a stable, versioned record format makes exports, summaries, and future sync safer.

## Core record

```ts
type PainEntry = {
  id: string;
  createdAt: string;          // ISO 8601 timestamp, stored with timezone offset
  updatedAt: string;
  occurredAt: string;         // defaults to now and is editable in the check-in
  regions: BodyRegionId[];
  intensity: number;          // overall/default integer 0–10
  sensations?: Sensation[];   // overall/default sensations
  areaDetails?: AreaDetail[]; // optional exceptions only
  precisionAreas?: string[];  // optional Tender detail IDs
  context?: EntryContext;
  note?: string;
};

type AreaDetail = {
  regionId: BodyRegionId;     // must also exist in regions
  intensity?: number;
  sensations?: Sensation[];
};

type EntryContext = {
  activities?: string[];
  triggerNote?: string;
  sleep?: 'poor' | 'okay' | 'good';
  stress?: 'low' | 'medium' | 'high';
  mood?: 'low' | 'neutral' | 'good';
  cycle?: 'period' | 'pre-period' | 'ovulation' | 'post-period' | 'other';
  medications?: MedicationLog[];
};

type MedicationLog = {
  name: string;
  dose?: string;
  takenAt?: string;
  perceivedEffect?: 'helped' | 'no-change' | 'not-sure';
};
```

## Supporting records

- `BodyRegion`: stable ID, label, side, view, grouping, and SVG path reference.
- `AppSettings`: theme preference, safety-message dismissal state (if any), and consent records. No health entry data is mixed into settings.
- `ConsentRecord`: version of notice, timestamp, selected purpose, and revocation timestamp when applicable.
- `BackupEnvelope`: schema version, export timestamp, and entries. It is a portable container, not an encrypted cloud backup.

## Guardrails

- IDs, timestamps, and schema versions are generated by the app, not manually editable.
- Editing preserves `id` and `createdAt`, updates `updatedAt`, and may change `occurredAt`.
- Older entries without `areaDetails` remain valid. Every selected region inherits the entry's overall intensity and sensations unless an exception exists.
- Area-detail records must refer to a selected region and cannot be duplicated.
- Tender precision IDs use the `tender-detail-` namespace. They supplement rather than replace the broader CHOIR region.
- Free text is always optional and is never silently sent anywhere.
- The app records what the person selected; it does not infer diagnoses, menstrual-cycle dates, triggers, or medication effects.
- Future AI requests use a temporary selected-data payload, not unrestricted database access.
- Deletion is an explicit permanent action with a second confirmation. Recovery depends on a previously downloaded backup.
